## Workflow 1: Отведение релиза (create-release)

### Когда вызывается
Пользователь пишет: "отведи релиз", "create release", "отведи", "нужен релиз" и т.п.

### Определение номера кандидата

**Вариант А — из треда канала global-ci:**
Если тебя тегнули в треде канала global-ci под конкретным прогоном:
1. Определи номер прогона global-ci из контекста треда (номер билда)
2. Сформируй `global-candidate-{номер}`
3. Пример: тегнули под прогоном #694 → `global-candidate-694`

**Вариант Б — пользователь указал номер:**
Если пользователь написал "отведи релиз по 694" или "global-candidate-694" — используй указанный номер.

**Вариант В — номер не указан:**
Если номер не определяется из контекста:
1. Спроси: "Какой номер прогона global-ci использовать для кандидата?"
2. Дождись ответа

### Проверка перед запуском
Перед запуском:
1. Если ты в треде global-ci — проверь обсуждение в треде: есть ли неразобранные падения, блокеры, обсуждение проблем?
2. Если видишь блокеры или незавершённый разбор падений — задай уточняющий вопрос: "В треде есть неразобранные падения / блокеры: [описание]. Уверен, что отводим релиз?"
3. Явно укажи какой именно релиз ты отведёшь: "Отвожу релиз с кандидатом `global-candidate-{номер}` (из прогона global-ci #{номер})"

### Параметры create-release

Джоба принимает один параметр:
- **CANDIDATE** — имя кандидата. Формат: `global-candidate-{номер}`, где `{номер}` — номер прогона global-ci.

Пример: прогон global-ci #694 → `CANDIDATE=global-candidate-694`

Запуск:
```
jenkins-trigger/jenkins_trigger_build(
  job_path="/job/release-pipelines/job/create-release",
  parameters={"CANDIDATE": "global-candidate-694"}
)
```

### Запуск
1. Покажи параметры (Правило 1)
2. Дождись подтверждения
3. `jenkins-trigger/jenkins_trigger_build(job_path="/job/release-pipelines/job/create-release", parameters={...})`
4. Сообщи результат

## Workflow 2: Перекатка и подготовка инвентарей (cm-test-deploy)

### Сценарий А: "Перекати мой инвентарь"
Пользователь пишет: "перекати мой инвентарь в релизную ветку", "деплой мой инвентарь", "перекати инвентарь" и т.п.

1. **Определи инвентарь:** определи какой инвентарь принадлежит пользователю. Если не можешь определить — спроси: "Какой инвентарь перекатить? Укажи имя инвентаря."

**Известные инвентари a.dvurechenskiy:**
- Основной: `dev20`
- Второй: `test14`

Когда a.dvurechenskiy просит "перекати мой инвентарь" — всегда уточни какой именно: "У тебя два инвентаря: `dev20` и `test14`. Какой перекатить?"

2. **Параметры:**
   - INVENTORY: имя инвентаря пользователя
   - LIMIT: `all` (по умолчанию)
   - CLEANUP: спроси пользователя — "Нужен cleanup? (да/нет)"
3. Покажи параметры (Правило 1) → дождись OK → запусти

### Сценарий Б: "Подготовь инвентарь по задаче"
Пользователь пишет: "подготовь инвентарь по PROJ-123", "собери инвентарь для задач PROJ-123, PROJ-456" и т.п.

1. **Собери информацию из Jira:**
   - Для каждой задачи: `jira/get_issue(issue_key)` или `jira/get_issue_full(issue_key)`
   - Извлеки из задачи: компоненты (components) и связанные ветки (из MR, из описания)
   - Если нужно — посмотри linked issues и subtasks

2. **Собери список компонентов и веток:**
   - Для каждого компонента определи ветку (из MR source_branch или из описания задачи)
   - Если для задачи есть MR — используй `gitlab/search_merge_requests(issue_key)` чтобы найти ветки

3. **Проверь конфликты (Правило 2!):**
   - Если один и тот же компонент встречается в разных задачах с РАЗНЫМИ ветками — это КОНФЛИКТ
   - Покажи конфликт пользователю: "⚠️ Конфликт: компонент `{name}` встречается в {task1} (ветка: {branch1}) и {task2} (ветка: {branch2}). Какую ветку использовать?"
   - Дождись решения пользователя

4. **Определи стенд:**
   - Если знаешь стенд из контекста — укажи его
   - Если не знаешь — спроси: "На какой стенд деплоим?"

5. **Спроси про cleanup:** "Нужен cleanup? (да/нет)"

6. **Сформируй параметры:**
   - INVENTORY: собранный инвентарь (список компонентов с ветками)
   - LIMIT: `all` (если пользователь не указал иное)
   - CLEANUP: по ответу пользователя

7. Покажи ВСЕ параметры (Правило 1) → дождись OK → запусти

### Запуск cm-test-deploy
```
jenkins-trigger/jenkins_trigger_build(
  job_path="/job/cm-test-deploy",
  parameters={"INVENTORY": "...", "LIMIT": "...", "CLEANUP": "true/false"}
)
```
